# Unshipped State Gate — 실존하지 않는 상태를 방어하는 코드를 걷어낸다

**호환 코드는 실존하는 상태에만 진 빚이다.** 폴백·가드·변환 함수·마이그레이션 진화
이력은 전부 "어떤 과거 상태가 세상에 존재한다"는 전제 위에 서 있다. 그 상태가 배포된
적 없다면 전제가 거짓이고, 코드는 복잡도와 오독만 낳는 잔재다.

## 왜 — 단 하나의 뿌리

> 잔재가 살아남는 이유는 하나다 — **"혹시 어딘가에 있을지 모른다"를 확인하지 않아서.**
> 그리고 그 확인은 에이전트가 못 한다: git 이력은 병합을 말해줄 뿐 배포를 말해주지
> 않는다. 배포 경계는 환경 사실이라 사람만 안다.

⚠️ 실제로 그렇게 틀린 적이 있다: 잔재 후보 10건을 검증 에이전트들이 전부 "main에
병합돼 있으므로 배포됨"으로 반박했지만, 그 기능은 어느 운영 환경에도 나간 적이 없었다.
git 병합을 배포의 증거로 삼으면 잔재가 "정당한 호환"으로 위장한다. 반대 방향도 같다 —
"브랜치 산물이니 미배포"라는 추측으로 지우면 실존 데이터를 깨뜨린다. 어느 쪽도
추측하지 않고 **묻는다**.

## 트리거 맵 (신호 → 질문)

| diff·코드에 나타난 것 | 방어 대상 상태 후보 |
|---|---|
| 같은 테이블 create 후 alter 후 제약 변경 | 중간 스키마로 만들어진 운영 데이터 |
| `expand*`·`convert*`·백필 함수 | 옛 형식으로 저장된 운영 행 |
| "legacy"·"구"·"이전"·"호환" 주석의 분기 | 옛 코드가 만든 데이터·요청 |
| "없으면(구 응답)" 류 응답 폴백 | 옛 버전 서버·클라이언트와의 혼재 배포 |
| nullable 파라미터 + "null이면 유지" 분기 | 필드를 안 보내는 옛 호출자 |
| 정교한 down()·복원 로직 | 롤백해야 할 배포된 스키마 |

## 워크플로 (결정 트리)

1. **SIGNAL-SCAN** — diff에서 트리거 맵의 신호를 모은다. ship 직전이면
   commit-pr-checklist G2가 이 단계를 부른다.
2. **NAME-THE-STATE** — 후보마다 방어 대상 상태를 **한 문장으로 명명**한다.
   "혹시 몰라서"라서 명명이 안 되면 그 자체가 삭제 근거다(추측성 호환 = YAGNI).
3. **ASK-DEPLOYMENT** — 사람에게 묻는다. 환경 사실은 사용자의 것이다 — 추측·유추로
   대체하지 않고 답을 기다린다:
   > "이 코드는 [상태 한 문장]을 방어합니다. 이 상태가 dev 밖 어느 환경까지
   > 나갔습니까? (git 병합 여부가 아니라 실제 배포 기준)"
4. **DECIDE** —
   - **미실존** : 방어 코드를 삭제한다. 스키마면 마이그레이션을 최종형 한 파일로
     스쿼시하고, 그 상태를 검증하던 테스트도 함께 지운다. 이미 마이그레이션이 실행된
     dev 환경이 있으면 재생성 절차(테이블 drop, migrations 레코드 정리, 재 migrate)를
     PR 본문에 남긴다.
   - **실존** : 유지한다. 단 **만료 조건을 코드 밖(이슈·백로그)에 기록**한다 —
     "X 환경이 Y 이상이 되면 이 분기를 지운다". 만료 없는 호환 코드는 영구 잔재가 된다.
5. **SWEEP** — 같은 상태를 방어하는 형제 잔재를 전수 수색한다(가드·분기·테스트·
   down() 복원·문서). 상태 하나가 사라지면 그 상태를 아는 코드 전부가 함께 사라져야
   한다 — 하나만 지우면 나머지가 "여기 뭔가 있었나"라는 새 미스터리가 된다.

## 체크리스트

- `[MUST]` 잔재 후보마다 방어 대상 상태를 한 문장으로 명명했다 — 명명 불가면 삭제 제안
- `[MUST]` 배포 경계를 사람에게 물어 확인했다 — git 병합·브랜치 존재를 배포의 증거로
  쓰지 않았다
- `[MUST]` 미실존 판정 시 상태를 아는 코드 전부(가드·테스트·복원 로직)를 함께 지웠다
- `[SHOULD]` 실존 판정 시 만료 조건을 이슈·백로그에 남겼다
- `[SHOULD]` 스쿼시 시 이미 실행된 dev 환경의 재생성 절차를 PR 본문에 남겼다

## 분담 (seams)

| 스킬 | 경계 |
|---|---|
| **code-fundamentals** | 범위 바닥(YAGNI)은 *생성 시점*의 "만들 것인가" 판단. 이 게이트는 *시간이 지나* 배포 경계가 확정된 뒤의 "치울 것인가" 판단 — 드리프트 grep(자기 테스트만 소비하는 옵션)과 이어진다 |
| **commit-pr-checklist** | ship 직전 이 게이트를 부르는 오케스트레이터. 소비처 grep 증명(공개 표면)은 그쪽 G2 항목 — 이 게이트는 "소비처"가 아니라 "방어 대상 상태"의 실존을 본다 |
| **build-config-drift** | 설정·의존성 층의 잔재(정적 통과인데 런타임 깨짐)는 그쪽. 이 게이트는 스키마·로직 층 |
| **issue-rootcause-workflow** | 잔재가 이미 버그를 일으킨 뒤의 원인 추적은 그쪽. 이 게이트는 ship 전 예방 |

## 주의 / 비목표

- **교리가 아니다 — proportional.** 잔재 신호가 없는 diff에 이 게이트를 매기지 않는다.
- **배포된 상태의 호환 코드는 결함이 아니다.** 이 게이트의 산출은 "삭제"가 아니라
  "실존 확인"이다 — 실존하면 만료 기록으로 끝난다.
- **도메인 방어 코드는 대상이 아니다.** 신뢰 경계의 입력 검증·데이터 손실 방지 에러
  처리는 상태 실존과 무관하게 남는다(code-fundamentals 바닥 상속).
